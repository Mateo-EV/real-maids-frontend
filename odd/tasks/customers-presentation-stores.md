Add root-provided capability stores in `src/app/features/customers/presentation/state`, delegating exclusively through existing use cases. 2. **S2** — User: "obviamente debes usar lo que hemos hablado en otros stores, como ttl, etc. Cualquier consulta que tengas hazmela antes de continuar". Reuse existing `createReadResource` and `createSessionReadScope`: shared ref-counted reads, freshness checked on read without polling, only success renews TTL, explicit forced retry, retained verified same-key data during refresh/error, query/owner isolation, bounded history and session clearing/cancellation/fencing, no SSR work or orphan root subscriptions. Do not change shared helpers or auth behavior.
3. **S3** — Accepted proposal: "Te propongo **2 minutos** para clientes, propiedades, contactos, preferencias y catálogos; **30 segundos** para leads, seguimientos e historial. Reutilizaría los helpers existentes y adaptaría también `CustomersStore`." User: "me parece perfecto". Apply 120000ms/30000ms accordingly, including customer details. Preserve effective server pagination; no local slicing or inferred totals.
4. **S4** — Accepted proposal: "Recuperé lo acordado: TTL sin polling, peticiones compartidas y cancelables, datos conservados durante actualización, invalidación tras escrituras y limpieza por sesión." Confirmed writes invalidate affected cached reads, fence older completions and refresh active observers if exposed, without replaying writes or optimistic totals. Failures preserve verified data. Keep independent capability loading/error/read/write states, typed safe errors and caller-owned subscriptions. Preserve backend authoritative permissions and sensitive data without logging.
