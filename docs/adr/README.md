# Architecture Decision Records

Los ADR describen decisiones de largo alcance. Estados válidos: `Proposed`, `Accepted`, `Superseded` y `Deprecated`.

| ADR | Decisión                              | Estado   |
| --- | ------------------------------------- | -------- |
| 001 | Angular + TypeScript                  | Accepted |
| 002 | Frontera REST/JSON interna            | Accepted |
| 003 | Routing consciente de permisos        | Accepted |
| 004 | Web responsive                        | Accepted |
| 005 | QuickBooks solo desde backend         | Accepted |
| 006 | Spartan UI + Tailwind CSS             | Accepted |
| 007 | SSR, hidratación y prerender          | Accepted |
| 008 | Vitest con builder oficial de Angular | Accepted |
| 009 | Organización por feature y capas      | Accepted |

Para una decisión nueva:

```markdown
# ADR-NNN: Título

- Estado: Proposed
- Fecha: YYYY-MM-DD

## Contexto

## Decisión

## Consecuencias

## Alternativas consideradas
```

Un ADR debe indicar si describe una decisión nueva, una decisión ya materializada que se formaliza, o si sustituye a otro ADR.
